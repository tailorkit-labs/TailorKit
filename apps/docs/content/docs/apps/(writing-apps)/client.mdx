## `defineClient`

Register one view map for each host slot your app supports:

```tsx
import { defineClient } from "@tailorkit/app";

export default defineClient({
  slots: {
    navbar: { "/": navigation },
    panel: { "/users": generalTools, "/users/detail": detail },
  },
});
```

Slot names and their supported view paths come from generated host bindings.
A globally declared view can only be registered under slots that list it. View keys
must match the path passed to `createView`. An omitted slot is unsupported.
A `false` view entry explicitly disables that view and stops ancestor fallback.

## `createView`

```tsx
import { createView } from "@tailorkit/app";

const detail = createView("/users/detail", {
  component: UserTools,
});

function UserTools() {
  const { workspaceId, user } = detail.useContext();
  return <UserActions user={user} />;
}
```

The hook returns the composed, typed context from the selected view and its
ancestors. It is available only while the ready component renders. Views render
nothing while host context is loading or in an error state. `createView` accepts
only a `component`; apps cannot provide loading or error components for host
context.

Each slot selects exactly one view, searching the active view followed
by ancestors. A detail view replaces the general view in the same slot.
Other slots resolve independently. Only the selected view and its ancestors
contribute readiness; descendant failures cannot block a general view.

Missing matches render nothing. Missing declared ancestor context produces an
error state. Neither loading nor error triggers fallback to another view.

`path`, `component`, and `useContext` are members of the returned view definition.
The client's `$meta` and `$runtime` properties are internal sandbox details.

See [Add views and slots](/docs/integrate/views) for host integration.

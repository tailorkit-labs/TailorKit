TailorKit apps run in a sandbox. That helps, but it does not make every value
safe automatically.

## Understand the trust boundary

TailorKit sandboxes app JavaScript for you, so embedded apps cannot directly
reach into your page or application state. Your host app still decides which
fields, callbacks, and actions are available.

The production rule is simple: expose the pieces an app needs, validate the
values it sends back, and keep side effects limited to the work your app
expects.

The runtime uses a hidden iframe with an opaque origin and executes the client
directly in that sandboxed document. The iframe allows scripts but not
same-origin access, and its content security policy blocks direct network
connections. The host still fetches app code,
passes context into the runtime, renders the returned UI, and executes approved
actions. Those host-controlled edges require the same care as any public API.

## Minimize view context

Every field published through `useView()` is visible to the app rendering that
view. Pass view models designed for the app contract, not database records,
sessions, access tokens, or broad route-loader objects.

Derive permissions on the server. Do not treat a hidden component or omitted
button as authorization.

## Validate component fields

Keep schemas narrow. Prefer enums, bounded numbers, booleans, and structured
objects over broad strings.

### Links and sources

<Callout title="Validate links">
  Do not render arbitrary strings as `href` or `src` values. Accept only safe protocols, usually
  `https:` and `mailto:`.
</Callout>

```ts title="./src/lib/tailorkit.ts" tab="Zod"
import { z } from "zod";

const Link = {
  fields: z.object({
    href: z.url({ protocol: /^(https|mailto)$/ }),
  }),
};
```

```ts title="./src/lib/tailorkit.ts" tab="ArkType"
import { type } from "arktype";

const Link = {
  fields: type({
    href: type("string.url").narrow((href) =>
      ["https:", "mailto:"].includes(new URL(href).protocol),
    ),
  }),
};
```

```ts title="./src/lib/tailorkit.ts" tab="Valibot"
import * as v from "valibot";

const Link = {
  fields: v.object({
    href: v.pipe(
      v.string(),
      v.url(),
      v.check((href) => ["https:", "mailto:"].includes(new URL(href).protocol)),
    ),
  }),
};
```

### Text and HTML

Treat long-form text as text, not markup. Avoid accepting raw HTML unless you
sanitize it before rendering.

## Keep callbacks UI-only

### UI events

Callbacks are for UI events like `onClick`, `onOpenChange`, and
`onValueChange`. Do not use them to call APIs, mutate records, or start billing
or auth flows.

### Trusted actions

For trusted work, expose a host-owned [action](/docs/actions).

Authorize every action using `context`, even if the UI only exposes it to a
particular role. Validate action input and output, view database queries to the
authenticated tenant, and avoid returning secrets or internal metadata.

## View app installation

Define a stable schema for each named installation boundary in `scopes`, such
as `user` and `organization`. Return their identity values under the same names
in `authenticate` rather than accepting them from an app request. Use stable
opaque IDs; these values are sent to TailorKit to match and display app
installations.

Keep project keys and CLI credentials on the server or developer machine. Never
include them in browser bundles or app-generated context.

## Constrain styling

### Styles and classes

Avoid arbitrary `style` objects, raw class names, and HTML. Prefer
[TailorKit primitives](/docs/layouts-and-styles) and theme tokens so apps can
feel native without controlling layout, positioning, or visual hierarchy.

### Sensitive UI

<Callout title="Keep trusted UI recognizable">
  Destructive, billing, auth, invite, role, and permission controls should look and behave like
  host-owned UI. Do not let an embedded app visually replace those flows.
</Callout>
